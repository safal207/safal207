## How to participate

1. Choose one open issue; read its scope, existing discussion and linked PRs.
2. Record the exact source revision and a minimal local or synthetic reproduction. Ask in that issue before making a broader change.
3. Share only sanitized evidence: no credentials, customer data, confidential screenshots, private traces or personal information.
4. For code changes, follow the project's license and contribution rules, keep the change focused, and include a regression or documentation update when applicable. A maintainer review is required; a passing test is not proof of acceptance.
5. Report negative results and uncertainty as well as successful runs. Use private contact or the repository's security route for sensitive findings. Never test third-party production systems without explicit authorization.

For AI PATH, feedback and wording suggestions are welcome in #56. A license was not found in the checked standard root locations (LICENSE, LICENSE.md, COPYING). The maintainer must clarify licensing and third-party asset rights before inviting code redistribution or general code contributions. No new license is assigned by this index.

## Maintainer review queue

- Verify current task status and existing implementation before publishing or assigning any additional task.
- Respond in the existing issue; record acceptance, rejection or next step with a reason.
- Do not equate bot-generated or maintainer-authored work with independent community participation.
- Clarify AI PATH licensing before requesting source-code PRs; retain the existing public learning experience.
- Do not begin outreach or promise response times without a separate decision.
